STC METRO CDMX - CONEXIÓN DE REPORTES COMPARTIDOS
=================================================

ARCHIVOS
- index.html, styles.css, app.js: sitio web.
- logo-route.png, publicidad-tecnm.png: imágenes.
- supabase-config.js: aquí se pega la URL y la clave pública de Supabase.
- supabase-client.js: funciones para consultar y registrar reportes.
- supabase_schema.sql: crea la tabla, índices y políticas de seguridad.

PASO 1. CREAR PROYECTO
1. Entra a https://supabase.com/ y crea una cuenta/proyecto.
2. Anota la contraseña de la base de datos en un lugar seguro.
3. Espera a que el proyecto termine de crearse.

PASO 2. CREAR LA TABLA
1. En Supabase abre SQL Editor.
2. Pulsa New query.
3. Abre este archivo supabase_schema.sql, copia todo su contenido y pégalo.
4. Pulsa Run. Debe terminar sin errores.

PASO 3. COPIAR CREDENCIALES
1. En Supabase abre Project Settings > API (o Connect/API Keys, según la interfaz).
2. Copia Project URL.
3. Copia la clave pública publishable (NO la service_role ni secret key).
4. Abre supabase-config.js y reemplaza:
   PEGA_AQUI_TU_PROJECT_URL por la URL del proyecto.
   PEGA_AQUI_TU_PUBLISHABLE_KEY por la clave pública.
5. Guarda el archivo.

PASO 4. PROBAR LOCALMENTE
Abre el sitio mediante un servidor local (por ejemplo, la extensión Live Server de VS Code),
no es necesario abrir supabase-config.js directamente. Registra un reporte y verifica que
aparezca en Supabase > Table Editor > reports.

PASO 5. PUBLICAR CAMBIOS
Sube TODOS los archivos actualizados al repositorio de GitHub, incluyendo los tres nuevos:
supabase-config.js, supabase-client.js y supabase_schema.sql.
GitHub Pages publicará la nueva versión. Abre la página en dos navegadores/dispositivos:
registra un reporte en uno y comprueba que aparece en el otro (la actualización automática
se realiza cada 15 segundos).

SEGURIDAD IMPORTANTE
- La clave publishable/anon puede estar en el navegador; la seguridad real está en RLS.
- NUNCA publiques la contraseña de la base de datos, service_role o secret key.
- Los visitantes pueden leer y crear reportes, pero no modificar ni borrar reportes ajenos.
- Para resolver/eliminar reportes se debe entrar al panel de Supabase (Table Editor) como
  administrador. Para permitir moderadores desde la web, se debe añadir autenticación.
- Los reportes son comunitarios y no son avisos oficiales ni datos en tiempo real del Metro.
- Esta primera versión no identifica a quien reporta ni limita spam; antes de una difusión
  grande conviene añadir CAPTCHA, autenticación opcional y moderación.

ADMINISTRAR REPORTES DESDE SUPABASE
En Table Editor > reports, puedes cambiar status a 'resuelto' y resolved_at a la fecha/hora
actual. También puedes borrar una fila desde el panel. Si prefieres SQL, abre SQL Editor:

Marcar un reporte como resuelto:
UPDATE public.reports
SET status = 'resuelto', resolved_at = now()
WHERE id = 'PEGA_AQUI_EL_UUID_DEL_REPORTE';

Eliminar un reporte:
DELETE FROM public.reports
WHERE id = 'PEGA_AQUI_EL_UUID_DEL_REPORTE';

Haz estas operaciones solo como administrador y verifica el UUID antes de eliminar.
